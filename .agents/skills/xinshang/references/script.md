> 完整规则见 `rules/02-xinshang.md`。


### 4. 批量扫多章（用通配）

## 四、规则项与 `[X]` 触发条件

| 项 | 触发 `[X]` 的情况 | 改法 |
|----|------------------|------|
| **字数 3000+** | 字数 < 2800 兜底 | 加事件 / 加对话 / 砍心理 / 不靠堆环境 |
| **破折号 0** | 出现 `——` `—` `–` `－` | 改逗号 / 句号 / 冒号 / 分号 / 重写 |
| **连续句号铁律** | 段内出现「句号 + 几字短句 + 句号」/ 段落句末符 >3 / 句号碎片化 | 改逗号合并 / 拆段 / 长短句搭配 |
| **零英文** | 出现 PPT/KPI/OKR/deadline/email/App 等 | 改中文 / 不写 |
| **零 AI 关键词** | 忽然 / 这一刻 / 仿佛 / 真正的 / 原来 / 缓缓 / 轻轻 / 静静（忽然仅限物理） | 删 / 换动作 / 换白描 |
| **段末符 ≤3** | 一段句号+问号+感叹号+省略号 >3 | 拆段 / 改逗号合并 |
| **单句逗号 ≤3** | 一句话内逗号 >3 | 拆句 / 改句号 |
| **对话格式** | `"X"母亲说，"Y"Z说，"W"` 逗号堆叠 | `"完整句。"母亲说，"新句。"` |
| **元叙事词无** | 出现「第 X 章」「上一章」「本章主题」「作者的话」「读者」「剧情」「小说」 | 删 / 改写 |

## 五、连续句号铁律（最高优先级）

> `rules/02-xinshang.md` 第一节。**这一项 `[X]` 即整章不通过，其它项不评分。**

### 触发样例

错 1：「他停住了。不是王。」
对：「他停住了，不是王。」

错 2：「他就是急。这种急法他熟得很。」
对：「他就是急，这种急法他熟得很。」

错 3：一段 5 个句号以上 / 全部是单句短段
对：长短句搭配

### 检测口径
- 一段句末符（句号 + 问号 + 感叹号 + 省略号）合计 ≤3
- 段内**不**出现「句号后紧跟几个字短句再句号」
- **不**每段都拆成单句短段（一句话一段贯穿全章是另一极端 AI 味）

### 高频陷阱词
`X问` `X说` `X没应声` `X应着` `X没再劝` 后面若还接句子 → 一律改逗号合并。

## 六、修复策略

### 字数不够（< 3000）
- 不要贴 2800 兜底
- 第一遍就写足 3000
- 如果 3000 字写不满 → 这章事件不够，**回去加事件**，不是加环境/心理

### 标点错误
- 破折号 → 逗号 / 句号 / 冒号 / 分号 / 重写
- 句号碎片 → 逗号合并
- 逗号超 3 → 拆句

### AI 关键词
- 忽然（仅物理）→ 改「突然」「猛地」（如果物理） / 删（如果是心理/时间）
- 这一刻 / 仿佛 / 真正的 / 原来 → 删或白描
- 缓缓 / 轻轻 / 静静 → 删或换动作

### 元叙事
- 「第 X 章」→ 删（章节卡信息在 47 顶部「A 第 N 章写完状态详情」节）
- 「上一章 / 本章主题 / 作者的话 / 读者 / 剧情 / 小说」→ 删或改写

## 七、跑完必做

1. **任何 `[X]` 必改到 `[OK]`**
2. 改完再跑一次，确认全 `[OK]`
3. 复制脚本输出到 47 顶部「A 第 N 章写完状态详情」节
4. 填 47 顶部「A 第 N 章写完状态详情」节：
   ```
   - 硬规则脚本：[OK]（修复 [X] 详见本节「修复记录」）
   ```

## 九、常见问题

### Q1：脚本找不到 Python
A：用绝对路径 `"F:/Program Files (x86)/python/python.exe"`。

### Q2：脚本报「文件不存在」
A：路径用**正斜杠** `/`，不是反斜杠 `\`。Windows bash 用 `/`。

### Q3：批量跑太慢
A：单章跑即可。批量只用于跨章不重复（`grep` 不走脚本）。

### Q4：脚本 `[X]` 但我手动看觉得没问题
A：脚本是硬规则层面的最低线。**听脚本的**。即使你「觉得」OK，也按脚本口径修。

### Q5：脚本 `[OK]` 但我感觉还有 AI 味
A：跑 6 Gate + 八轮审查（软规则）。脚本只覆盖硬规则，软规则靠人工/子代理。
