# Workflow · /写六章（单会话闭环）

> 单会话一人分饰两职的闭环流程，与 `/写一章` `/审一章` `/继续下一章` 三条互斥、不共用闸门。
> 一次连写六章并逐章跑脚本自检，六章写完交**独立子代理**按 `审核CLAUDE.md` 全量审。
> 打回的 P0/P1 全部返修后再起新子代理复审，循环到六章零 P0/P1 才结束。
> 轮次上限 4 轮；到顶仍不通过就停下来报给用户，不许自判通过。
> 本流程不写 `创作记录/` `审核记录/`，全部通知输出在对话里；项目里只落六章正文和 47 顶部一行进度。
> 47 顶部为 **本流程唯一的「状态详情」载体**：六章每章的脚本结果、字数、修复记录、复审结论、P0/P1 清单等全部在对话里回填。

---

## 一、触发与定位

**触发命令**：`.claude/commands/写六章.md`（可带章号段，如 `43-48`）

**确定目标章**：
- `$ARGUMENTS` 有章号段 → 取该段
- 否则 → 读 47 顶部 + 最后一章章号推 6 章

**轮次上限**：4 轮（写→审→改→再审→…→零 P0/P1 结束）。4 轮仍未零 P0/P1 → 停下，列剩余问题与位置，交用户决定。

---

## 二、第一轮：连写六章

### 1. 一次性读全资料（不每章重读）
- `47_中间人转发话术.md` 顶部
- 章节卡 39（前 50 章已填 8 字段；第 51 章起空白）
- 大纲 38、人物 08/36、伏笔 13、时间线 16
- 上一章 + 上上章正文
- 项目宪法 43/44/CLAUDE.md 节选

### 2. 一章一设计 → 写 → 自检
每章按 `workflows/write-chapter.md` 第三节 12 字段设计 + 第四节写正文 + 第五节 6 Gate 自检。

**六章并行禁忌**：六章是**顺序连写**，不是一次性写完。每章先单独完成设计→自检→脚本 `[OK]` 才进下一章。

**写第 N+1 章前必读**：第 N 章成品（避免与已写成的混淆/重复）。

### 3. 跨章不重复自检（六个章之间的）
- 现实场景六章不重样
- 心界过渡六章不重样
- 意象六章不堆在同一物
- 配比六章接近（不出现 6 章全心界 / 全现实）

### 4. 不写创作记录 / 不写审核记录
本流程只在对话里通知用户，**不在 `novel/创作记录/` `novel/审核记录/` 写任何东西**。两目录本流程期间保持原状。

---

## 三、第一章脚本自检

每章写完立即跑：

```bash
python novel/工具/硬规则自检.py novel/正文/.../N_第N章_标题.md
```

`[X]` 必须当场改到 `[OK]`，再写下一章。

---

## 四、落正文

每章保存到 `novel/正文/.../N_第N章_标题.md`。

**更新 47 顶部**（**只更新一行**，不写其他记录）：

```
## 当前：/写六章 进度 N/6（第 N 章《xxx》已脚本自检 [OK]）
```

六章全部落正文后，把 47 顶部改为：

```
## 当前：/写六章 六章已写完，等独立子代理复审（轮次 1/4）
```

---

## 五、起独立子代理复审

**用 general-purpose 子代理**，传：
- 6 个章文件路径
- 审核宪法 `审核CLAUDE.md`（14 轮 + 48 规则）
- 本 Skill 的 `rules/01-deslop.md` + `02-xinshang.md`
- 47 顶部当前进度
- 子代理回复结构：每章 P0/P1/P2 清单 + 总结论

**子代理**：
- 跑硬规则脚本（每章）
- 跑 14 轮审查
- 不许改正文，只列问题 + 建议改法
- 结论只能「通过」或「不通过（N 处 P0 + M 处 P1）」

---

## 六、返修（按 P0/P1 改）

**P0/P1 必改**（P2/P3 不必改）。

返修原则：
- 改一处 → 重新读该段上下文 → 改完不破坏前后衔接
- 改 P0/P1 引发新问题时优先回退到原表达 + 找别的改法
- 不擅自把 P2 当 P1 改（避免越改越坏）
- 不擅自删情节

返修完跑脚本 + 改完自检每章。修完通知用户「改完了」。

**更新 47 顶部**：

```
## 当前：/写六章 第 M 轮返修完，等独立子代理复审（M/4）
```

---

## 七、起新子代理复审

复审范围：
- 只复核上次 P0/P1 改没改完
- 顺手扫一眼有没有新副作用（连带损伤）
- 不重新 14 轮全量（那是新轮次）

**如果复审仍有 P0/P1**：再返修 → 再复审。**轮次计数 +1**。

**如果复审零 P0/P1**：进入第八步。

---

## 八、闭环

**更新 47 顶部**：

```
## 当前：/写六章 六章已通过（轮次 X/4）
```

回复用户「六章写完了，通过 X 轮，零 P0/P1」+ 六章字数 + 落正文章节文件路径列表。

---

## 九、到顶未通过（轮次 ≥4 仍不通过）

**停下，不许自判通过**。

回复用户：
- 已写 N 章
- 剩余 P0/P1 列表（按章/行号/问题/建议改法）
- 已耗轮次 4/4
- **让用户决定**：继续返修（突破 4 轮上限）/ 接受现状 / 跳过 / 改设定

**不擅自处理**。

---

## 十、纪律

- **不写 `创作记录/` `审核记录/`**（本流程只走对话）
- **不自主 git 提交**
- **不替用户/人物/作者悟**
- **不擅改核心设定**
- **不与 `/写一章` `/审一章` `/继续下一章` 共用闸门**（本流程独立）

---
