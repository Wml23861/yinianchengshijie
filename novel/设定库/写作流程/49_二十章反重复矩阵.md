**落点参考**（**2026-09-02 二次修订**：参考清单，不是封闭的 5 种必选）：
- 落点是开放的方向——下面是常见落点，**作者可自由发明新落点**（如"明心在梦里成了一只鸟""明心被心界人物错认成别人"等任何新形态都允许）：

- **同一个心界人物间隔参考 ≥ 3 章**——但**不是死锁**（如果剧情需要"急行人连续 2 章出现并产生不同影响"，完全允许）

- **进出心界过渡不要让读者明显感到"上一章也是这么进的"**——判断由作者完成，**不机械卡"相邻两章不重样"**
- **"明心遇到问题 → 反思 → 进心界"**是 AI 常用的"问题→心界解决"模式，**避免连续多章**（但**偶尔用完全可以**）
- **"电话 / 微信 / 手机通知"触发**是 AI 最爱的触发，**避免连续多章**——但**偶尔用完全可以**（手机就是日常工具）

  - 白天走路忽然进入

  - **本章不开心界门**——明心在现实里待一整天，什么也没发生，离开（**最高级的过渡**：没有过渡）

**核心原则**：触发是"让故事流动"的问题，**不是"必须用 N 种之一"的问题**。

## 二、查表流程（动笔前 2 分钟）

```
1. 打开 49_反重复矩阵.md
2. 查表 1：现实场景最近 N 章用过什么 → 本章作者按"是否重复"判断
3. 查表 2：心界人物落点最近 N 章 → 作者按"是否镜子"判断（不是机械轮换）

5. 查表 4：最近 N 章开头形式 → 作者按"是否给读者新意"判断
6. 查表 5：最近 N 章触发结构 → 作者按"是否流水账"判断
7. 查表 6：触及维度 → 不必刻意轮换——5 维度是参考不是清单
8. **查表 7：心界出场登记** → 本章是否需要心界？若是新人物/旧人后续，立约登记
```

**没有"必须换 3 项"的硬规则**——**作者回头读一遍，如果觉得"读者会感到重复"，就换**；**如果觉得"读者不会觉得重复"，就不必换**。**判断权在作者/A/B**。
