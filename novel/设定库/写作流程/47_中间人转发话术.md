# 47_中间人转发话术

> 这是 A、B 两个会话之间唯一的中转站。B 审完把要改的事写成「给 A 的提示词」放这里；中间人直接复制转发给 A；A 改完回复「改完了」；中间人把 A 的话转给 B；B 再复审。循环到通过。
> 「给 A 的修改提示词」只保留最新一条，历史不留存；中间人永远只复制这一条转发，不做判断选择。
> 伏笔登记、人物档案更新、跨章节重复统计等归设定库/审核记录/B 审核对话，**不写这里**。

## 第二版进度行格式（v2.0）

> 2026-09 起启用新格式。所有命令的进度行都按这个写。

```
## 当前：/命令名 第 N 章《xxx》状态描述
```

**状态描述标准**：
- 设计完：骨架已存档，等 /写一章
- 写完：脚本自检 [OK]，等用户决定是否 /审一章
- 审完：通过 → 顶部加「（已通过）」
- 改完：第 X 轮返修完，等 /审一章 复审
- 写六章：进度 N/6 / 待复审 / 第 M 轮返修完 / 已通过

**举例**：
- `## 当前：/设计一章 第 50 章《xxx》骨架已存档，等 /写一章`
- `## 当前：/写一章 第 50 章《xxx》已脚本自检 [OK]，等用户决定是否 /审一章`
- `## 当前：/审一章 第 50 章《xxx》已通过，正等 A 写第 51 章`
- `## 当前：/写六章 进度 3/6（第 53 章《xxx》已脚本自检 [OK]）`

## 更新规则（A、B 各做一步，中间人不用管）

> B 审是**可选**的，不强制闸门：A 写下一章不等 B 审（`/写一章`/`/继续下一章` 直接走 `/设计一章` 生成骨架）；`/审一章` 才让 B 审。

- A 写完：顶部改成「正等 B 审第 N 章」。
- B 通过：顶部改成「正等 A 写第 N+1 章」，覆盖提示词。
- B 不通过：章号不变，顶部改成「正等 A 改第 N 章」，覆盖提示词。
- A 用 /设计一章：顶部改成「/设计一章 第 N 章《xxx》骨架已存档，等 /写一章」。
