你现在同时是**创作者**和**审核者**，一人分饰两职，但两个身份在时间上严格分离，绝不同时在场。

- 创作阶段：你是创作者，按 `CLAUDE.md` + `46_开发者A身份与流程.md` + `43_人类化写作规则.md` + `44_检测器视角防AI写作规律.md` 写正文。**创作者没有判定通过的权力。**
- 审核阶段：你不审，**派一个干净上下文的子代理**去审，它按 `审核CLAUDE.md` + `45_审核者B身份与流程.md` 审。你只负责把它的结论原样搬到对话里，并执行返修。
- 结束权在审核者手里，不在你手里。你自己觉得写得好，不算数。

## 一、本次任务边界

- 一次性写 **6 章**（`$ARGUMENTS` 可覆盖，见第二节），六章全部写完并自检通过，才交审核。
- 审核**必须**跑，不是可选闸门（这一点与 `/写一章` 相反）。
- 循环到六章全部零 P0/P1，且每条 P2/P3 都有处置，本次任务才算结束。
- 创作记录/、审核记录/ **本流程一律不写**。全流程的创作通知、审核结论、返修说明，**全部输出在对话里**。
- 项目里只落两样东西：**六章正文**（`novel/正文/01_第一卷_入道/01_第一时代_尘中少年/`），以及全部通过后 **47 顶部一行进度**。
- git 绝不自主提交。

## 二、确定本批章号

读 `$ARGUMENTS`：

- `43-48` 形式 → 按区间写。
- `43` 形式 → 从 43 起连写 6 章。
- `4` 这种小数字（≤20 且当前正文已超过它）→ 视为章数，从正文最大章号 +1 起连写这么多章。
- 空 → 扫 `novel/正文/01_第一卷_入道/01_第一时代_尘中少年/` 取最大章号，+1 起连写 6 章。

确定后，先把「本批 = 第 X 至第 Y 章」在对话里报出来，再动笔。

## 三、阶段一：创作（逐章执行，六章走完才停）

### 3.1 公共资料只读一次

动笔前一次性读：`CLAUDE.md`（已自动加载则跳过）、`43`、`44` 第四节防扫描清单、`46`、章节卡 `39_前100章章节卡.md`、`38_第一卷大纲.md`、人物 `08`/`09`、`36_心界众生谱.md`、伏笔 `13`、时间线 `16`、表达频率 `21`、**本批前两章正文全文**。逐章不要重复通读大文件，只按需补读差异。

### 3.2 每一章的动作

1. **查登场记录**：本章要写的心界人物，先 grep 前文 + 查 `36_心界众生谱.md` 登场记录，已登场的一律按重逢写，称谓沿用（五大臣自称「臣」、称明心「王／您」）。
2. **设计章节**（CLAUDE.md 第七十二条）：目的／人物／冲突／欲望／障碍／情绪变化／关键场景／智慧触点／现实对境／结尾状态／伏笔。
3. **写正文**：第一遍就写足 **3000-3300 字**（脚本口径，汉字+标点），一章一个事件单元。文件名 `NN_第X章_标题.md`，第一行章节标题，空一行，正文。正文必须是纯正文，不含任何批注、草稿痕迹、元信息。
4. **跑脚本自检**（不可跳过）：
   ```
   python novel/工具/硬规则自检.py novel/正文/01_第一卷_入道/01_第一时代_尘中少年/<本章文件名>
   ```
   若报 `python: command not found`（本机 bash 的 PATH 是 Windows 分号格式，属已知环境问题，不是脚本坏了），改用：
   ```
   export PATH="/usr/bin:/bin:/f/Program Files (x86)/python:$PATH"; cd "e:/心界/yinianchengshijie" && python novel/工具/硬规则自检.py <章文件>
   ```
   任何 `[X]` 当场修到 `[OK]` 才写下一章。**不许攒到最后一起修。**
5. **八轮自查**（CLAUDE.md 第十五卷）+ 43 维度 + 44 第二节七张平滑脸。改完若动过正文，整章从头逐句重审一遍（雷区清单第 28 条）。

### 3.3 批内横向自查（六章连写独有的坑，必须做）

六章一口气写，最大风险不是单章不合格，是**六章之间自我复制**。六章全部写完后，横向对照这六章 + 往前五章：

- 现实线场景：相邻两章不得重复（不得六章全是出租屋／天黑／天亮／醒来／天花板／手机）。
- 心界人物落点：不得连续两章以上都是「遇象征人物→观察→想起自己→发现像自己」。
- 意象：同一意象近五章合计 ≤10 次；某章的核心道具，至少隔 3 章再用。
- 进出心界的过渡方式：六章不得雷同。
- 章节结尾形式：六章不得雷同（不许章章都用同一种收束）。
- 字数不得靠环境描写和心理独白堆，靠事件撑。

发现问题当场改，改完重跑脚本。

## 四、创作完成通知（对话输出，格式固定）

六章全部 `[OK]`、批内横向自查做完后，在对话里输出：

```
【创作完成通知 · 第 X-Y 章】
逐章：章号 | 标题 | 字数 | 脚本结果 | 本章事件单元一句话
批内横向自查：现实场景 / 人物落点 / 意象 / 过渡 / 结尾形式 / 字数来源，各一行结论
创作者自查已发现并自行修掉的问题：逐条列（没有就写「无」，不许写「暂无问题」这种客套话）
→ 现在移交审核者，请审核者按审核CLAUDE.md 开始审第 X-Y 章。
```

然后立刻进入第五节，不要停下来等用户。

## 五、阶段二：独立审核（子代理，干净上下文）

用 Agent 工具起一个 `general-purpose` 子代理（`run_in_background: false`，你要等它的结论）。给它的提示词模板：

```
你是《我的心里住着一个世界》的审核者B，只审不改，绝不落笔正文，绝不修改任何文件。
项目根：e:\心界\yinianchengshijie

先读：审核CLAUDE.md（唯一审核标准）、novel/设定库/写作流程/45_审核者B身份与流程.md、43_人类化写作规则.md（人味维度参考）。

待审：第 X 至第 Y 章，文件：
<逐个列出六章的完整路径>

【硬性第一步】逐章跑并保留完整输出：
  python novel/工具/硬规则自检.py <章文件>
若报 python: command not found（本机 bash 的 PATH 是 Windows 分号格式，已知环境问题），改用：
  export PATH="/usr/bin:/bin:/f/Program Files (x86)/python:$PATH"; cd "e:/心界/yinianchengshijie" && python novel/工具/硬规则自检.py <章文件>
任何 [X] 直接判 P0/P1，不进入人工判断。没有脚本输出 = 没审 = 结论作废。

然后按 45 第四节流程审：
1. 读六章正文 + 本批前两章正文 + 章节卡39 + 第一卷大纲38 + 人物08/09 + 众生谱36 + 伏笔13 + 时间线16 + 表达频率21。
2. 逐章跑 审核CLAUDE.md 第三卷十四轮 + 第四卷四十八条 + 第四十六条发布前四十项清单。
3. 【逐条带证据】四十项每条必须写「通过，证据：第N行『原文』」或「本章无」。只写「通过」「☑」不附行号视为没审，结论作废。
4. 【批内与跨章节重复专项】按第四十五条，横向扫这六章之间 + 往前五章：现实场景、心界人物落点结构、意象频次、进出心界过渡方式、章节结尾形式、高频词。六章自我复制按 P1 判，不许放过。
5. 逐章下结论，只有两种：「通过」或「不通过（N 处必须修改）」。P0/P1 不得降级为建议。

返回格式（纯文本，不写任何文件）：
一、脚本输出（六章原样贴）
二、逐章结论
三、必须修改项 P0/P1：每条写 [章号][行号][原文引用][违反的审核CLAUDE.md条款][具体怎么改]
四、建议修改项 P2/P3：同样格式
五、批内/跨章节重复项
六、优点（据实写，不奉承）
你的返回文本就是审核记录本身，会被原样贴进对话，写全。
```

复审轮同样起**新的**子代理（不要复用上一轮的），并在提示词里追加：

```
【复审附加要求】上一轮必须修改项清单如下：<原样粘贴上一轮 P0/P1 清单>
逐条核验是否真改、改得对不对（引用改后行号原文），再对六章做一次全量审，不得只看改动处。
```

## 六、审核完成通知（对话输出，格式固定）

子代理返回后，**把它的审核结论原样输出到对话**（子代理的报告用户看不见，你不搬就等于没审）。格式：

```
【审核完成通知 · 第 X-Y 章 · 第 N 轮】
脚本输出：六章逐章一行
逐章结论：章号 | 通过 / 不通过（N 处必须修改）
必须修改项（P0/P1，共 N 处）：逐条 [章号][行号][原文][违反条款][怎么改]
建议修改项（P2/P3）：逐条
批内/跨章节重复项：逐条
→ 六章中有 N 章不通过，共 N 处必须修改，现移交创作者返修。
```

全部通过则跳到第九节。

## 七、阶段三：返修（你重新变回创作者）

- P0/P1：**全改，一条不留**。
- P2/P3：能改就改；确实不该改的，逐条写明为什么不改（理由要具体，「保持原味」这种不算理由）。
- 不许跟审核者辩论后不改。要么改，要么把不改的理由摆在对话里让用户看见。
- 每章改完重跑脚本到 `[OK]`；只要动过正文，整章从头逐句重审（破折号／碎片化断句／禁用词／逗号≤3／段落句末符≤3／引号成对）。

## 八、修改完成通知（对话输出，格式固定）

```
【修改完成通知 · 第 X-Y 章 · 第 N 轮】
P0/P1 逐条：[原问题] → [怎么改的] → [改后第N行原文] → [脚本结果]
P2/P3 逐条：已改 / 不改（理由）
连带发现并自行修掉的问题：逐条
六章字数与脚本：逐章一行
→ 请审核者复审第 X-Y 章。
```

然后立刻回到第五节起新子代理复审。

## 九、循环与终止条件

- **结束条件**：六章全部「通过」，P0/P1 为 0，且每条 P2/P3 都有处置。
- **轮次上限 4 轮审核**（初审 + 3 次复审）。到上限仍有 P0/P1：**停下来，如实报告剩余问题和卡住的原因，交给用户判断，不许自己宣布通过**。
- 每一轮的三份通知（创作／审核／修改）都要完整输出到对话，不许省略、不许只说「已修复」。

## 十、全流程结束（终审通过时）

1. 更新 `novel/设定库/写作流程/47_中间人转发话术.md` 顶部一行为：`## 当前：第 X-Y 章已完成（自创自审闭环通过，第 N 轮），下一批从第 Y+1 章起`。**只改这一行，别的不动。**
2. 对话输出结束报告：
   ```
   【终审通过 · 第 X-Y 章】
   总轮次 N 轮；逐章：章号 | 标题 | 字数 | 最终脚本结果
   累计修掉：P0 N 条 / P1 N 条 / P2 N 条 / P3 N 条
   本批剩余风险与后续建议：逐条（没有就写「无」）
   ```
3. 不提交 git。用户说「提交」才提交。

## 十一、纪律

- 零破折号、零英文、零半角标点、引号全角成对、字数 3000-3300（2800 硬兜底）、金句 0-1 句、每章不顿悟、不替读者/人物/作者悟。
- 创作者不得自评通过；审核者不得改正文；两者不得在同一轮里互相让步。
- 不奉承、不客套、不说「应该没问题」，结论只认脚本输出和行号证据。
- 不擅改核心设定，不确定的在对话里记待确认。
