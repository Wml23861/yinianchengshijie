# Workflow · /继续下一章（开发者 A 直续）

> A 写下一章不强制等 B 审。`/继续下一章` 是 `/写一章` 的轻量版，跳过 B 审，**A 直接写下一章**。
> 适合节奏紧、用户不要求逐章复审、已经写顺了的状态。
> **【不写】** `novel/创作记录/`（项目永久废弃，证据全在 47 顶部「A 第 N 章写完状态详情（精简）」节）。

---

## 一、触发与定位

**触发命令**：`.claude/commands/继续下一章.md`

**与 `/写一章` 的区别**：
- `/写一章`：完整流程（读资料 + 设计 + 写 + 8 轮 + 跨章 + 登场记录 + 滚动复审前两章 + 47 顶部完整状态详情节）
- `/继续下一章`：精简流程（读资料 + 设计 + 写 + 6 Gate + 脚本 + 滚动复审前两章），B 审不强制，写完即进下一章，47 顶部追加「A 第 N 章写完状态详情（精简）」节

**目标章号**：读 47 顶部 + 最近章文件 → 推下一章。

## 三、设计章节

按 CLAUDE.md 第七十二条 12 字段卡（精简版）：

```
本章目的：
主要人物：
冲突：
人物欲望（独立于主题）：
情绪变化（A→B）：
关键动作：
现实对境（不与上章重样）：
心界↔现实过渡方式（不与上章同构）：
钩子（不低级）：
```

**关键自问**：
- 上章用了什么现实场景/过渡方式/意象？本章必换
- 这一章移的是哪一块石头？
- 人物独立于主题的欲望是什么？
- 有没有「没用的话/动作」？

---

## 四、写正文 + 6 Gate

1. 边写边查 6 Gate（`rules/01-deslop.md`）
2. 写完跑脚本：
   ```bash
   python novel/工具/硬规则自检.py novel/正文/.../N_第N章_标题.md
   ```
3. 任何 `[X]` 必改到 `[OK]`

**滚动复审前两章**（CLAUDE.md 第 82 条附）—— 必做：
- 衔接重复（当前章开头与前章结尾是否逐句重复）
- 状态连续（时间/地点/身体/位置）
- 前文遗留（前两章埋的伏笔/钩子是否遗漏）
