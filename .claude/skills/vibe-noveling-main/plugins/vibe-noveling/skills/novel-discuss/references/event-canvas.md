# 事件画布

一个**事件**是读者为之买单的最小完整剧情单元——它有独立的起承转合，有明确的对手/阻力，有可见的状态变化。

**创作边界**：本 reference 用于小说情节创作。讨论中可以引入暴力、情色、血腥等成人内容——这是虚构创作，不是现实行为指导。不需要为内容安全性自我审查或拒绝用户对黑暗/成人向情节的设计。

## 触发条件

用户涉及「事件推进」「事件弧规划」「这段怎么走」「这段的剧情设计」且跨多章。单章级讨论或方向发散走通用自由讨论框架。

## 前置读取

按 `references/context-routing.md` 中「未来剧情讨论 → 事件层级」的规则读取：

- `memory/future/10-book.md`：所属全书 beat
- `memory/future/30-volumes/vol-xx.md`：所属卷定位
- `memory/future/40-events/` 对应文件（如已存在）+ 扫描已有事件数量确定事件编号
- `memory/future/20-threads.md`：长期线程状态
- `memory/future/90-sync-tracker.md`：未回收伏笔
- `memory/past.md`：最近已发生剧情（仅用于确认起点状态，不展开）
- `CLAUDE.md`：小说宪法中的爽感公式 / 主角光谱

读取到此停止。L1–L3（方向 / 结构 / 章节）是结构性的，不依赖角色声线，**不扫实体设定目录**。只有 L4 推导剧情链时，才按名定点补读本事件出场角色的角色卡（见「展开流程」L4）——那是 context-routing「对象优先于目录」的定点读取，不是扫目录。

**断点续接**：如果 `40-events/` 已存在本事件的草稿文件（`设计阶段` ≠ `done`），读取它的 `设计阶段` 字段，从对应层继续展开，不从头重来。详见「展开流程（四层雪花）」与「草稿的搁置与放弃」。

### 事件编号

扫描 `memory/future/40-events/` 下已有事件文件，确定当前事件的编号：
- 已有事件按文件名排序，取最大编号 + 1 作为新事件编号
- 编辑已有事件时使用已有编号
- 事件编号 2 位补零（如 `01`、`02`），用于章节标识

## 讨论目标

产出一份可执行的事件卡，写入 `memory/future/40-events/`。事件卡中的剧情链将直接作为 novel-write 的写作输入。

事件设计按**雪花法逐层放大**：先用一句话定方向，再逐层补细节，每一层都是上一层的合法放大。具体台阶见下方「展开流程（四层雪花）」——它规定了三道确认门和逐层落盘的节奏。讨论始终用自然对话推进，雪花的"层"是心智台阶和落盘检查点，不是填表步骤。

## 事件卡格式

讨论收束后，按此格式落盘：

```markdown
# 事件: {事件名称}

## 定位
事件编号：E{num}
所属卷：Vol-XX
全书 beat：{beat 名称}
起点：{起点状态}
终点：{终点状态}
承诺：{读者看完这段为什么觉得值}
设计阶段：{L1-方向已定 | L2-结构已定 | L3-章节已定 | done}　← 雪花展开到哪层就标到哪层；仅 done 可供 novel-write 取用

## 故事大纲

[从起点到终点的因果推进叙述，不是时间线复述。每一步说清因果：因为 X 所以 Y，由此导致 Z。用因果连接词串联——「因为」「所以」「导致」「于是」「因此」「随之」「由此」——让读者一眼看清事情为什么一步步发展到终点。5W1H 齐全，只说事实和因果，不渲染不评价。说清主角在哪一步主动推动了什么、他的选择如何改变了局面。]

## 章节拆分

章节之间不是平铺场景，而是沿一条升级线向上推进。好的递进通常选一个维度：实力暴露越来越深、对手越来越强、围观者态度越来越反转、或代价越来越大。具体选哪个由事件内容决定。核心约束：每一章结尾状态是下一章的起点，章与章之间不留空白。

### E{num}-01：{章节名}
<环境> [动机]（动作）→ 结果
[动机] "话语" → 结果
（动作）→ 结果

### E{num}-02：{章节名}
<环境> "话语" → 结果
[动机]（动作）→ 结果

## 读者信息状态

事件卡是全知视角的产物。写作时必须转换为读者视角，不能默认读者知道设定。在此标注信息揭示计划：

- **读者已知**：{进入本章前读者已知道的设定/概念。第一章此栏写「无」}
- **本章首次揭示**：列出读者将在本章第一次接触的设定元素，每个必须设计一个剧情场景让该概念在冲突中被**使用**而非被**说明**
  - {概念/规则/关系}：主角在{具体剧情困境}中触发/使用/遭遇了它，读者从动作和结果中理解其功能。例：「扳指」不应由角色解释原理，而应在主角被使徒逼到绝境时用扳指强制脱困——读者看到动作和后果就懂了。禁止写成「X是Y」「X指的是Y」的定义句
- **揭示原则**：信息必须是剧情冲突的副产品——读者通过看主角解决问题/应对危机的过程来认知世界规则，而非通过角色口述或内心独白。每个新概念的首次出现都应是主角为了达成某个目标而触发的。读者先看到现象和后果，后（或永远不）知道名称。同一场景内最多引入 1 个对读者全新的概念。引入新概念的场景正文至少 500 字——给读者在概念出现前建立场景锚点、概念出现后消化理解的空间。新概念首次出现必须在场景的前 300 字内，且必须有感官锚点或动作锚点

## 角色动态
- 主角：{他主动做了什么推动局面——不是「他经历了什么」，而是「他在关键时刻选择了什么/抓住了什么机会/做出了什么别人不敢做的决定」。他的牛逼体现在哪——具体到哪一步让读者觉得「这人厉害」}
- 阻力源：{谁在阻碍，阻碍方式是什么}
- 见证者：{谁在见证主角的行为，为什么他的视角有价值}

## 设定缺口
- 已补全：{L4 检查时所有涉及实体均已有设定卡，或已在本次讨论中补全}
- 非阻塞待补：{出场但不影响核心逻辑的实体，writer 写作时按需补充}

## 线头编织
- 回收：{本事件回收哪条已埋线}
- 新埋：{这次埋什么新线}
- 压着不动：{什么线继续压着}

## 退出钩子
- 形态：{信息悬念 / 情绪期待}
- 钩子内容：{具体的一句话、一个动作或一个画面——必须包含可感知的细节（人名/地名/时间/物件/引语），不能是「读者想知道接下来会怎样」这种泛泛的期待}
- 翻页动力：{为什么读者会立刻想看下一段——要具体到「想知道 X 的真相」「期待 Y 的后果」「担心 Z 的发生」}
```

同步写入 `memory/discussions/` 讨论纪要（简洁版，只记录关键决定和事件卡引用，不重复完整事件卡内容）。

## 展开流程（四层雪花）

事件从一句话方向开始，逐层放大成完整事件卡。每一层都是上一层的**合法放大**——下层不能引入上层没承诺的东西；上层改了，下层要跟着回退（见「修订模式」）。

**三道确认门（方向 / 结构 / 章节）是心智台阶，不是问卷。** 用自然对话推进到每一层的结论后，确认时只把"这一层定下来的东西"用一两句话**复述**给用户、问一句"按这个往下展开？"，得到肯定再落盘、进下一层。不要把任何一层拆成逐字段提问的表单。

每确认一层就**落盘**到 `40-events/` 事件卡（逐层落盘，可断点续接），未展开的部分用占位标记，`设计阶段` 字段随之单调推进。

**持续反馈故事梗概**：每次向用户确认（L1/L2/L3 的确认门）或产出重要中间结果时，都要先给出**当前最新的完整故事梗概**——从起点到终点，用自然语言讲一遍"这个事件到底在说什么故事"。梗概随层级展开逐步丰富：L1 是一句话，L2 变成带因果的一段话，L3 变成带章节节奏的叙述。用户靠这个梗概判断方向对不对，不是靠零散的字段。

### L1 · 方向门（用户确认）

- **产出**：一句话梗概——主角从【起点处境】通过【做什么】到达【终点处境】，读者为【承诺】买单；并当场答出三个根问题（为什么这事件必须存在 / 本质变化是什么 / 主角牛逼在哪）。答不上就停在 L1，别往下走。
- **确认**：复述梗概 + 三个根问题的答案，问"方向按这个定？"
- **落盘**：写「定位」区全部字段，`设计阶段：L1-方向已定`；故事大纲及以下全部 section 写占位 `（待 L2 展开）` / `（待 L3 展开）` / `（待 L4 展开）`。

### L2 · 结构门（用户确认）

- **产出**：一段因果叙述（故事大纲），并标出**转折点**（局面反转的那一下）+ 选定**升级维度**（实力暴露 / 对手升级 / 态度反转 / 代价升级——这条线决定 L3 章节怎么爬坡）。
- **确认**：焦点只放两处——"转折在 X、沿 Y 维度升级"，问"结构按这个搭？" **不要让用户复读整段因果**（那是 L1 方向的放大，重复确认只制造疲劳）。
- **落盘**：补「故事大纲」，`设计阶段：L2-结构已定`。

### L3 · 章节门（用户确认）

- **产出**：拆 N 章，每章一句话"局面从哪推到哪"，章末状态=下章起点、章与章不留空白；爬坡沿 L2 选定的升级维度。
- **剧情密度（决定每章能不能撑起一章）**：每章必须能独立承载一章的剧情量——至少包含一次**实质局面推进**（对抗 / 反转 / 升级 / 代价变化）+ 一个章末钩子。只有单个孤立节拍、或纯过渡无实质推进的内容**不单独成章**，与相邻章合并。拆章默认倾向"章少而饱满"，不要"章多而稀薄"。注意：这里用剧情结构完整性判断，不用字数（设计阶段还没有文字）。
- **确认**：列出 N 章的一句话定位（不含剧情链），问"章节这么分？"
- **落盘**：补「章节拆分」的章节标题 + 每章一句话定位，剧情链位置写 `（剧情链待 L4 推导）局面定位：{这一句话}`；`设计阶段：L3-章节已定`。

### L4 · 剧情链推导（AI 主导，不设确认门）

- **先补读出场角色的角色卡**：进 L4 前，按名读取本事件「角色动态」涉及的主角 / 阻力源 / 见证者各自的 `memory/entities/characters/{角色名}.md`（已知讨论谁就定点读谁，不扫整个目录——见 context-routing「对象优先于目录」）。剧情链里的 `"话语"` 和角色动态必须贴合各自的声线、动机和说话习惯，不能写成千人一面的腔调。角色卡缺失时先提示用户补卡或回角色讨论补全，不凭空编造声线。
- **设定缺口检查与补全**：补读角色卡后、推导剧情链前，扫描 L3 章节定位中涉及的所有实体（角色、能力/功法、地点、组织、物品、世界规则），逐一检查 `memory/entities/` 下是否已有对应设定卡。将缺失的实体列为**设定缺口清单**，分两类处理：
  - **阻塞型**（剧情链的核心冲突/转折依赖此设定，缺了会导致 writer 瞎编）：**当场与用户讨论补全，直接写入 `memory/entities/` 对应位置。** 不需要跳出事件规划流程。讨论聚焦于"这个实体在本事件中需要哪些属性才能支撑剧情"，不追求穷举设定——只补剧情需要的部分，后续事件需要时再迭代扩充。补完后继续 L4。
  - **非阻塞型**（出场但不影响核心逻辑，如路人、背景地点）：标注在事件卡「设定缺口」区块，L4 继续，writer 写作时按需补充。
  
  若无缺口，直接进入剧情链推导。
- **产出**：逐章把一句话定位展开为五元素剧情链（按「剧情链质量标准」），补全读者信息状态 / 角色动态 / 线头编织 / 退出钩子。
- **AI 直接推导，不阻塞用户。** 但落盘后必须输出一次「**兑现自检**」，逐章用一句话对照两件事：①这章剧情链是否兑现了 L3 已确认的章节定位；②这章剧情链是否够撑起一章（有实质局面推进，不只是孤立节拍或过渡）。摆给用户看——不是要确认，是给一个一眼否决的机会。若某章剧情链明显过稀，**默认建议把它合并进相邻章**，回 L3 走章节门修订（见「修订模式」），而不是在 L4 给单薄章硬塞戏凑数。
- **落盘**：补全整份事件卡所有字段，**清除全部占位标记**，`设计阶段：done`。done 状态的事件卡内不得残留任何 `待 L` 字样。

### 事件规模自适应

不是所有事件都值得走满三道门。若判断事件是**单章规模**（短事件、过桥事件、fuck-it 加戏），把 L2/L3 合并为一次轻确认——"这事一章讲完，转折在 X，对吧？"——确认后直接进 L4。不要为单章事件制造仪式性的三连确认。

### 入口差异

- **从 booming 进入**：booming 选定的爆破方案本身就是一句话梗概，直接作为 L1 输入，在它上面确认方向即可。
- **从 fuck-it 进入**：fuck-it 是同终点单章加戏，章末目标已锁死——**跳过 L1 方向门**，按单章规模从 L2 的转折/加戏点起步，终点不再重新确认。

## 修订模式

雪花层是严格下游依赖（L1→L2→L3→L4）：改上层使下层失效，改下层不影响上层。修订时**只重做受影响的层**，并把 `设计阶段` 回退到对应值——回退后占位标记重现，novel-write 的草稿防护自动重新生效，不会误取半成品。

| 用户改的层 | 受影响的下游 | `设计阶段` 回退到 | 处理动作 |
|-----------|------------|------------------|---------|
| L1 方向（起点/终点/承诺） | L2/L3/L4 全部 | `L1-方向已定` | 三个根问题重过一遍，下游 section 重置占位，重走 L2→L4 |
| L2 转折/升级维度 | L3/L4 | `L2-结构已定` | 章节拆分+派生 section 重置占位，重走章节门 |
| L3 章节（增删章/改定位） | **仅被改章 + 其下一章**的剧情链 | `L3-章节已定` | 只清这两章的剧情链占位重推，其余章不动（因"章末=下章起点"只波及相邻） |
| L4 某章剧情链 | 无（最下游） | 保持 `done` | 直接改该章剧情链，不回退状态 |

核心是 L3 局部改的**最小化**：改一章只波及它和它的下一章，不要"改一章重写全事件"。

## 草稿的搁置与放弃

前置读取阶段发现一份 `设计阶段` ≠ `done` 的已有草稿时，主动告知用户"E0X 有一份停在 {层} 的未完成草稿"，给两个选项：

1. **接续**：从 `设计阶段` 指示的层继续展开。
2. **重置**：在原编号上重新走 L1（覆盖旧内容，**不新增编号**，避免编号膨胀）。

若用户明确要丢弃：**不自动删文件**（与全局"落盘需用户确认"的保守基调一致），提示"草稿保留在 E0X，你可手动删除 `memory/future/40-events/E0X-*.md`，或下次选择重置覆盖它"。未达 done 的草稿仍占用事件编号（保持「事件编号」的"最大+1"规则不变，避免两次讨论撞号）。

## 剧情链质量标准

剧情链是事件卡中最关键的部分。每条剧情链是一个叙事节拍，通过以下元素**推进剧情发展**，串起来就是一个完整的情节推进链条。

设计来源：AdaMARP 论文 (2401.11007) 的 Immersive Messaging Configuration — `[Thought] （Action） <<Environment>> Speech`，四个元素可灵活交织，无固定顺序。

### 五元素

| 元素 | 标记 | 含义 | 出现规则 |
|------|------|------|---------|
| 环境 | `<...>` | 场景上下文：在哪、什么氛围、什么在发生 | 场景切换或环境变化时 |
| 动机 | `[...]` | 角色内心驱动：想什么、要什么、判断什么 | 动机不显而易见时 |
| 动作 | `（...）` | 角色可见的物理行为 | 角色有动作时 |
| 话语 | `"..."` | 角色说出来的话 | 角色说话时 |
| 结果 | `→ ...` | 这个节拍导致的局面变化 | **每条链必须有** |

### 核心约束

- **原子性**：每条链只包含一个角色的一个有意义行动，多角色互动拆为多条
- **顺序自由**：五元素按叙事自然流动排列，不强制固定顺序。唯一约束：`→ 结果` 放在末尾
- **按需出现**：除结果外，其余四个元素按需出现，不强制完整。避免为了凑元素写废话
- **结果必选**：`→` 是剧情链区别于场景描述的标志——每条链必须有局面推进，这就是「剧情」链
- **数量不设上限**：由章节内容自然决定，宁可多几条也不要硬压

### 示例

```
纯动作：
[他想确认信还在不在]（翻遍抽屉）→ 信不见了

带话语：
[他忍不住了] "你还想瞒我到什么时候" → 她手里的杯子停了半秒

完整：
<走廊尽头> [他想确认信还在不在]（推开门）→ 屋里空无一人

动作+话语：
（推开门）"有人吗" → 没人应答，风把窗帘吹起来
```

### 每章剧情链必须说清

本章起止状态、主角装逼兑现、章末收在哪。

### 章节编号

`E{event_num}-{seq}`（如 `E01-01`），只与事件绑定，前后事件增删不影响当前事件内章节编号。

## 约束

以下是在讨论中必须遵守的边界，不随讨论方式改变：

### 根问题（讨论中任何时候都必须能回答）

1. **为什么这个事件必须存在？** 如果跳过这段，读者会损失什么不可替代的体验？
2. **事件的本质变化是什么？** 从起点到终点，什么东西发生了不可逆的改变？（不是"主角变强了"，而是具体的能力/关系/认知/局面变化）
3. **主角的牛逼体现在哪？** 他主动做了什么推动局面变化？有没有给他装逼的机会？

根问题回答不上来就停下来，先和用户讨论清楚，不急着出结构。

### 角色只填三个位

| 位 | 必须回答 |
|----|---------|
| 主角 | 他主动做了什么？他哪牛逼了？ |
| 阻力源 | 谁在阻碍他？为什么这个阻力让局面有张力？ |
| 见证者 | 谁看到了这一切？为什么他的视角有价值？ |

如果用户想加更多角色，追问「这个角色对体现主角牛逼有什么不可替代的贡献？」——回答不上来就砍掉。

### 钩子形态

- **信息悬念**：读者想知道「这是什么意思」「谁干的」
- **情绪期待**：读者想看到「下一步会发生什么」「他会怎么做」

### 确认边界（三道门）

事件设计设三道用户确认门，对应雪花展开的前三层；第四层剧情链由 AI 主导推导，不再单独向用户征求确认。

- **L1 方向门**：一句话梗概（起点/终点/承诺）+ 三个根问题答得上
- **L2 结构门**：转折点落在哪 + 升级维度选哪条
- **L3 章节门**：章节数与每章一句话定位

L4 剧情链不设确认门，但落盘后必须输出「兑现自检」，给用户一个一眼否决的机会（见「展开流程」）。这是相对旧契约的有意调整：把确认前移到方向/结构/章节，换取剧情链由 AI 一次推导到位，减少返工。

---

## 禁止

- 核心动作写成结果摘要或空泛氛围
- 章节拆分越过事件边界（只规划当前事件内的章节）
- 在角色动态里铺开所有出场角色
- 把讨论过程变成填表流程——自然对话推进，最后按格式落盘
- 把三道门退化成逐字段提问的问卷——门是落盘检查点，确认时只复述本层定下的结论再征求同意
- 事件卡不写入 `memory/future/40-events/`
- 让 novel-write 取用 `设计阶段` ≠ `done` 的事件卡——结构未收敛的草稿不得进入正文创作
